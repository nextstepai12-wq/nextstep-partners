# دليل مدير الشراكات

## 1) الدخول
افتح `…/admin.html` وادخل ببريدك وكلمة المرور. لا يُسمح إلا للحسابات المسجّلة في جدول `partner_admins`. تنتهي الجلسة تلقائيًا بعد **30 دقيقة خمول**. خيار «تذكّرني» يحفظ الجلسة على الجهاز: استخدمه على جهازك الشخصي فقط.

## 2) الأدوار
| الدور | قراءة | تعديل (حالة/أولوية/وسوم/ملاحظات) | تحديد جماعي | حذف | نسخة JSON |
|---|:--:|:--:|:--:|:--:|:--:|
| owner (مالك) | ✓ | ✓ | ✓ | ✓ | ✓ |
| admin (مشرف) | ✓ | ✓ | ✓ | — | ✓ |
| viewer (مشاهد) | ✓ | — | — | — | — |

الصلاحيات تُفرض داخل قاعدة البيانات (RLS)، فإخفاء الأزرار في الواجهة ليس هو الحماية الحقيقية.

## 3) التبويبات
- **لوحة المؤشرات:** إجمالي الطلبات، الجديدة، قيد العمل، المعتمدة، آخر 7 أيام، وما يحتاج متابعة؛ وتوزيع الحالات والدول والمجالات والاهتمامات والطلبات اليومية آخر 30 يومًا.
- **الشركاء:** بحث (الاسم/البريد/الرمز/الدولة/الوسوم)، فلاتر (حالة، نوع، دولة، مجال)، ترتيب، تحديد جماعي، تصدير CSV للنتائج المفلترة. اضغط أي صف لفتح التفاصيل.
- **سجل النشاط:** كل ما حدث: طلب جديد، تغيير حالة، ملاحظات، تعديل بيانات، حذف، مع المنفّذ والوقت.
- **دليل الاستخدام:** ملخص داخل اللوحة.

اختصارات: `/` للبحث، `Esc` لإغلاق التفاصيل.

## 4) دورة حياة الطلب (مقترحة)
| الحالة | معناها | الإجراء المقترح |
|---|---|---|
| جديد | وصل ولم يُراجَع | راجعه وتواصل. بعد 3 أيام يظهر في «تحتاج متابعة» |
| تم التواصل | تواصلتم وبانتظار الرد | سجّل في الملاحظات ما اتُّفق عليه وموعد المتابعة |
| قيد التعاون | اتفاق مبدئي وتفاصيل جارية | حدّد الأولوية والوسوم (مثل: ورشة، رعاية) |
| معتمد | شريك رسمي | — |
| مرفوض | لا يناسب حاليًا | اكتب السبب في الملاحظات (داخلية فقط) |
| مؤرشف | مغلق أو مكرر أو قديم | — |

> هذه مقترحات تنظيمية، وليست التزامات زمنية معلنة للشركاء. الصفحة العامة لا تعد بمدة محددة للرد.

## 5) ما يراه الشريك
في «تتبّع طلبك» (رمز + بريد) يرى فقط: اسم جهته، الحالة بصياغة مهذّبة، آخر تحديث. **لا يرى** ملاحظاتك ولا أولويتك ولا وسومك ولا اسم المراجع. عند «مرفوض» تظهر له عبارة: «لم يتم اعتماد الطلب في الوقت الحالي…».

## 6) الأولوية والوسوم والملاحظات
- **الأولوية:** عالية/عادية/منخفضة لترتيب العمل.
- **الوسوم:** حتى 10، كل وسم حتى 30 حرفًا (مثال: `ورش`، `رعاية`، `جامعة`).
- **الملاحظات:** حتى 5000 حرف. سجّل الوقائع لا الانطباعات الشخصية، فقد يُطلب الاطلاع على بيانات الجهة قانونيًا.

## 7) التصدير
- **CSV:** يصدّر النتائج الحالية بعد الفلترة بترميز UTF-8 مع BOM ليفتح العربية صحيحًا في Excel. الخلايا التي تبدأ بـ `= + - @` تُحيَّد تلقائيًا لمنع حقن الصيغ.
- **JSON (مالك/مشرف):** نسخة احتياطية كاملة.
- الملفات تحتوي بيانات شخصية: احفظها في مكان آمن واحذفها بعد الاستخدام ولا تشاركها عبر قنوات غير آمنة.

## 8) طلبات أصحاب البيانات (تعديل/حذف/اطلاع)
1. تأكد من هوية الطالب: يراسلك من البريد المسجّل نفسه أو يقدّم رمز المتابعة.
2. **تعديل:** افتح الطلب وعدّل الحقول (يُسجَّل التعديل في السجل).
3. **حذف:** يتم من المالك: افتح الطلب ← «حذف الطلب» ← اكتب الرمز للتأكيد.
4. سجّل تاريخ الطلب وما نُفّذ في مكان داخلي خارج اللوحة.

## 9) استكشاف الأخطاء
| العرَض | السبب والحل |
|---|---|
| «البريد أو كلمة المرور غير صحيحة» | تحقق من الحساب في Supabase ← Authentication ← Users |
| «هذا الحساب غير مخوّل» | لا يوجد صف للمستخدم في `partner_admins`: شغّل SQL إضافة المشرف |
| لا تظهر بيانات | تحقق أنك شغّلت `03_security_rls.sql` وأن دورك في `partner_admins` صحيح |
| «لا تملك صلاحية التعديل» | دورك `viewer` أو لم تُشغَّل سياسات التعديل |
| فشل حفظ حالة | قد تكون الجلسة انتهت: حدّث الصفحة وادخل من جديد |
| لوحة فارغة بعد تغيير مشروع Supabase | حدّث `CONFIG` ووسم CSP في `admin.html` |
