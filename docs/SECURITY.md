# الأمان والحوكمة

## 1) ما الذي نحميه؟
بيانات الجهات الشريكة وأشخاص التواصل فيها (أسماء، بريد، أرقام واتساب، معلومات تجارية)، وملاحظات الفريق الداخلية، وصلاحيات الإدارة.

## 2) الضوابط المطبّقة
| الضابط | أين | ماذا يمنع |
|---|---|---|
| **RLS على كل الجداول** | `03_security_rls.sql` | الزائر لا يقرأ ولا يعدّل ولا يحذف أي صف؛ يضيف طلبًا جديدًا فقط |
| **أدوار الإدارة** (owner/admin/viewer) | جدول `partner_admins` + `partner_is_admin()` | تصعيد الصلاحيات؛ المشاهد لا يعدّل، والمشرف لا يحذف ولا يضيف مديرين |
| **سياسة الإدخال الصارمة** | `partners_insert_public` | الزائر لا يفرض `status` أو `notes` أو `priority` أو `tags` أو `reviewed_by` |
| **قيود الصحة** | `01_schema.sql` | بريد/هاتف/رابط غير صالح، `javascript:` في الروابط، نصوص ضخمة |
| **حدود المعدّل** | `partners_guard` | 30 طلبًا/10 دقائق عامًا، 3 طلبات/يوم لكل بريد |
| **فخ الروبوتات + فحص السرعة** | `index.html` | الإرسال الآلي الساذج |
| **سجل تدقيق** | `partners_audit` | إنكار التعديل؛ يسجّل المنفّذ والقيم القديمة/الجديدة؛ لا سياسة كتابة له من الواجهة |
| **حقول ثابتة** | `partners_before_update` | تغيير `ref_code` أو `consent` أو `created_at` بعد الإدخال |
| **تتبّع آمن للشريك** | `partner_track()` | لا يكشف إلا الحالة عند تطابق الرمز والبريد، ولا يكشف أي بيانات شخصية |
| **خروج تلقائي بعد الخمول** | `admin.html` | جلسة مفتوحة على جهاز متروك |
| **CSP + منع التضمين + noindex** | `admin.html` | حقن سكربتات خارجية، clickjacking، فهرسة اللوحة |
| **تهريب المحتوى** | `admin.html` | كل نص قادم من الزوار يُهرَّب قبل العرض، والروابط تُعرض فقط إن كانت http(s) |
| **تحييد حقن الصيغ** | تصدير CSV | `=HYPERLINK(...)` وأخواتها في Excel |
| **تأكيد كتابي للحذف** | `admin.html` | الحذف غير المقصود |
| **أسرار خارج الريبو** | `private.partner_secrets` | توكن تيليغرام لا يظهر للزوار ولا في الكود |
| **حماية متقدمة (اختيارية)** | Turnstile + Edge Function | الإغراق الآلي المتقدم |

## 3) المفاتيح
- **publishable/anon key:** مصمَّم ليكون ظاهرًا في كود المتصفح. أمانه يعتمد على RLS، وقد اختُبرت (انظر TESTING.md).
- **service_role / secret key:** لا يوضع في أي ملف في الريبو أبدًا. يُستخدم فقط داخل Edge Function عبر أسرار Supabase.
- **توكن تيليغرام:** يوضع فقط داخل SQL Editor (جدول `private.partner_secrets`) وليس في الملفات.

## 4) قائمة ما قبل الإطلاق
- [ ] نفّذت `01` إلى `04` بالترتيب، ورأيت صفّك في `partner_admins` بدور owner.
- [ ] عطّلت **التسجيل العام** في Supabase Authentication.
- [ ] كلمات مرور الإدارة طويلة وفريدة (12+).
- [ ] راجعت `CONFIG` ووسم CSP في `admin.html` (رابط مشروعك).
- [ ] لا يوجد `service_role` أو توكن في الريبو (ابحث عن `service_role` و`bot` في الملفات).
- [ ] أجريت «اختبار ما بعد النشر» في SETUP.md كاملًا.
- [ ] راجعت `privacy.html` ووافقت على كل ما التُزم به فيها (انظر البند 6).
- [ ] قرّرت سياسة النسخ الاحتياطي (JSON شهريًا على الأقل).

## 5) حدود معروفة (قرارات واعية)
1. **لا مصادقة ثنائية (MFA) في لوحة الإدارة حاليًا.** الحماية الحالية: كلمة مرور قوية، تعطيل التسجيل العام، خروج تلقائي. لإضافة MFA لاحقًا يلزم تعديل واجهة الدخول وسياسات RLS لتشترط `aal2`.
2. **CSP عبر وسم meta** أضعف من ترويسات الخادم (GitHub Pages لا يتيح ترويسات). يُخفّف الخطر كون اللوحة بلا مكتبات خارجية وكل المدخلات تُهرَّب.
3. **حدود المعدّل عامة:** يمكن لمهاجم مصرّ استهلاك حد الـ30 طلبًا/10 دقائق فيحجب التسجيل مؤقتًا. الحل: تفعيل المستوى الثاني (Turnstile) أو مراقبة الجدول.
4. **لا تحقق من ملكية البريد** عند التسجيل: يستطيع أي شخص إدخال بريد غيره. لذلك التتبّع يتطلب الرمز أيضًا (40 بتًا عشوائيًا) ولا يكشف إلا الحالة.
5. **التتبّع العام بلا حد معدّل** على مستوى قاعدة البيانات؛ التخمين غير عملي (رمز عشوائي 40 بتًا + بريد مطابق)، لكن يمكن إضافة حد لاحقًا عبر Edge Function.
6. **النسخ الاحتياطية** التلقائية تعتمد على خطة Supabase؛ لا تفترض وجودها.
7. إن فعّلت **إشعار تيليغرام** فبيانات الطلب (اسم، بريد، هاتف) تمر عبر خوادم تيليغرام. حدّث `privacy.html` إن رأيت ذلك مهمًا (الصياغة الحالية عامة: «أدوات داخلية مثل تطبيقات المراسلة»).

## 6) التزامات وردت في سياسة الخصوصية (تأكد أنك تلتزم بها)
- لا تبيع البيانات، وتقصر الاطلاع على فريقك المخوّل.
- تنفّذ طلبات التعديل والحذف.
- تحتفظ بالبيانات ما دام التواصل أو الشراكة قائمين أو حتى طلب الحذف.
- النص صيغة عامة مبنية على ما تفعله المنظومة تقنيًا، **وليس استشارة قانونية**. راجعه مع مختص إن كانت شراكاتك تخضع لتشريعات حماية بيانات (مثل GDPR) خارج فلسطين.

## 7) الاستجابة للحوادث (مختصر)
1. **اشتباه بتسريب كلمة مرور مشرف:** غيّر كلمة المرور من Supabase، واحذف صفّه من `partner_admins` مؤقتًا، وراجع «سجل النشاط».
2. **إغراق بالطلبات:** فعّل المستوى الثاني (SETUP §9) أو أغلق الإدخال مؤقتًا: `revoke insert on public.partners from anon;`، ثم احذف الطلبات الوهمية.
3. **تسريب مفتاح سري (service_role أو توكن بوت):** دوّره فورًا من لوحة المزوّد، وراجع السجلات.
4. **طلب حذف عاجل من شريك:** اتبع ADMIN_GUIDE §8.
